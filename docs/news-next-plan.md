## 1. 目標の言いかえ

**宇宙のニュースを見たあと、「それって何？ いまどうなってる？」を、3分で、出典つきでつかめる場所。**

1枚で答えること（「5つの問い」）：

| 問い | 答え方 | いまある部品 |
|---|---|---|
| 何？ | 一言（何をするものか）と運用機関 | 「一言でわかる」ページ（`web/missions/`、20件） |
| いま何が起きた？ | ニュースになった出来事を、日付・出典つきで1行 | 出来事のカード（`curation/events/`）。ページには**まだ出ていない** |
| どこ？ | いまの位置・距離（地球のまわり／遠くを見る部屋／いまどこ） | 地球の画面・遠くを見る部屋・`mmx/now/` |
| これまで→これから | 打ち上げ〜いま〜次の予定のタイムライン | 次の出来事（M8）。ページの中には**まだない** |
| どれくらい？ | 身近なものさし（光で何時間・月までの何倍・ISS の高さとくらべて） | 遠くを見る部屋・いまどこの字幕にある。ページには**まだない** |

## 2. 市場の見立て（客観）

### 2.1 ニュースのあと、人はどこへ行くか

| 行き先 | 強み | 弱み（中高生が「概要をつかむ」用に見て） |
|---|---|---|
| 検索の AI の要約（Google の AI による概要など） | 速い・その場で終わる | 図・いまの位置がない。出典は小さい。古いことがある |
| Wikipedia | 網羅 | 長い・専門用語。「いま」の更新はまちまち |
| 公式（JAXA・NASA など） | 正確 | ミッションごと・機関ごとに分かれる。大人向け・英語のことも |
| ニュースサイト（ニュースのまとめ・専門メディア） | その日の出来事に強い | 出来事の断片。全体像（これまで→これから）は別の記事 |
| X・YouTube の解説 | 入口として強い（若い世代はニュースを SNS で知る） | 出典が見えにくい。質がまちまち |

数字で分かること：

- **文字だけの要約は、検索の AI に置きかえられつつある。** Pew Research Center（2025、米国の成人の約6.8万回の検索）：AI の要約が出ると、結果のリンクを押す割合が 15% → 8%（[Campaign Live](https://campaignlive.com/article/1-click-through-rate-google-ai-overviews-killing-publishers/1927692)）。Authoritas（英国、2025-07）はデスクトップで 47.5%・モバイルで 37.7% 減と推定（[Press Gazette](https://pressgazette.co.uk/media-audience-and-business-data/google-ai-overviews-publishers-report-clickthroughs-authoritas-report/)）。Google は「全体の流入に大きな減少は見ていない」と反論（[PPC Land](https://ppc.land/google-disputes-pew-study-showing-ai-overviews-reduce-clicks-by-half/)）。どれも Google 自身のデータではない
- **若い世代はニュースを SNS で知る。** 10〜20代はニュースを得るメディアの1位が SNS（モバイル社会研究所 2024-01、[J-CAST の記事](https://www.j-cast.com/2024/05/23484387.html?p=all)）。12〜18歳では「信頼できる情報源」はテレビ 60.1%・SNS 9.9%（MMD研究所 2019、[リセマムの記事](https://resemom.jp/release/prtimes/20191204/58851.html)。古い調査）→ 入口は SNS、確かめる先は「信頼できる」場所、という分かれ方がありうる
- 2025年の中高生のニュースの情報源を直接調べた新しい数字は、今回は見つからなかった（推測しない）
- 宇宙の言葉の検索数（「MMX とは」など）は取れていない。Search Console を入れれば、VOYASCOPE に来た検索だけは分かる（5.）

### 2.2 空いている場所

- 「文字の要約」で勝負すると、検索の AI と Wikipedia に負ける。**VOYASCOPE にしかないのは「いまの位置が動いて見える」「これまで→これからが1本の線で見える」「事実ごとに出典」**。この3つを、ニュースの次の1枚にまとめる
- ニュースの出来事の多くは**予定されている**（打ち上げ・到着・フライバイ・分離・流星群・日食）。予定の出来事は先にページを用意できる（MMX の予告ページと「いまどこ」はその形で、打ち上げの日に間に合った）
- 予定にない出来事（事故・発見・急な延期）は、出典の確認に時間がかかる。**速報では勝負しない**。「いまの状態：確認中（公式の発表を待っています）」と書けることを強みにする

### 2.3 勝ち筋と負け筋

| | 中身 |
|---|---|
| 勝ち筋 | ① ニュースになる言葉（機体・出来事の名前）で、ページがある ② そのページが出来事から24時間以内に新しい ③ 文字の要約にない「動く位置・線・ものさし」がある ④ X の投稿・共有のリンクから、そのページへ直接入れる |
| 負け筋 | ① ページが古い（ニュースのほうが新しい）② ニュースの言葉がない（名前が違う・ページがない）③ 開くと重い・地球の画面を通らないと答えに着かない ④ 文字だけで、AI の要約と変わらない |

## 3. 目標（案）：数で決める

| 指標 | 意味 | 計り方 | 目安（案） |
|---|---|---|---|
| **カバー率** | 日本語で報じられた宇宙のニュースの主題のうち、VOYASCOPE にページがある割合 | 「ニュース台帳」（4. N0）で月ごとに数える | 2026-12：50%・2027-03：70% |
| **新しさ** | 出来事のあと、ページの「いま何が起きた」が24時間以内に直った割合 | 台帳の日時とコミットの日時 | 予定の出来事：100%（先に用意）・予定にない出来事：出典が出てから24時間以内 |
| **3分で着く** | ニュースの言葉から、5つの問いの答えまで | ページ単体で読み込み・表示（CI の size・速さの基準を当てる） | 地球の画面を通らずに答えが出る |
| 外から来る量（参考） | 検索・X からページに来た数 | Search Console（検索の語と表示回数）。アクセス解析を入れるかは 6. | 数値目標はデータが取れてから |

カバー率と新しさは、アクセス解析なしでリポジトリの中だけで計れる。最初はこの2つを主にする。

## 4. 進め方（案）：マイルストーン M13「ニュースの次に開く」

| | 段 | 開くとできること | 先に要るもの |
|---|---|---|---|
| N0 | ニュース台帳 | 月ごとに「日本語で報じられた宇宙の主題」と「VOYASCOPE のページの有無・新しさ」の表。カバー率が分かる | Grok の速報（すでにある）を台帳の形で頼む依頼文。台帳は非公開の `voyascope-research` に |
| N1 | 一言ページを「ニュースの次」の形に | `web/missions/*` に「いま何が起きた？」（最新の出来事1行・日付・出典）「これまで→これから」（打ち上げ〜次の予定の線）「どれくらい？」（ものさし1つ）を足す。いまの位置へのボタン（地球の画面・遠くを見る部屋・いまどこの該当の場所を直接開く） | `build-summaries.mjs` が出来事のカード・軌道・距離から作る（手で書かない）。ページごとの OGP 画像（共有で見える） |
| N2 | 予定から先回り | 30日以内の出来事は、ページが出来事の7日前までに「これから」になっていることを CI で確かめる（なければ落とすか警告） | 出来事のカードとページのつながり（`mission` の ID） |
| N3 | ニュースの言葉を増やす | 台帳でページがなかった主題を、多い順にカード化（例：ロケット、天宮・神舟、スターシップ、アルテミス3号、日食・月食、彗星）。1か月に数件 | チャッピーの調査（C 番号）→ 照合 → `curation/`（いまの手順のまま） |
| N4 | 入口 | ページの題を「〇〇とは？」の形に・別名（略称・英名・愛称）を構造化データに。X の投稿のリンク先を、ホームではなく該当のページに | robots.txt はいまのまま（検索・引用は許可） |

順番：N0 と N1 を先に（ページの形が決まらないと N3 で量を増やせない）。N2 は N1 と同じ時期に。N3 は台帳がたまってから。

### N0・N1 でやったこと（2026-10-30）

- **N0 ニュース台帳**：
  - Grok への依頼に **G5「ニュース台帳（月1回）」** を足した（`prompts/src/grok.md`）。対象の月に日本語のニュースで報じられた宇宙の主題を、日付・主題・別名・予定／予定外・記事の URL・公式 URL の表で
  - 台帳は非公開の `voyascope-research` の `research/news-ledger/YYYY-MM.csv`。列：`date,topic,aliases,kind,media_url,official_url,page`（`kind` は scheduled / unscheduled、`aliases` は「|」区切り、`page` は空なら名前で探す・ないと分かっているものは「-」）。Grok の報告は Claude Code が記事・公式を開いて照合してから書く
  - 数える：`node scripts/news-coverage.mjs <台帳.csv>` → カバー率・新しさ・ページのない主題（多い順。N3 の候補）。新しさは、関係するカード（とその events）のコミットが、予定の出来事は30日前〜当日、予定外はその日〜翌日にあれば「間に合った」
  - 流れ：月はじめにオーナーが Grok に「今回のタスク：G5／対象：YYYY-MM」→ 報告を Claude Code に貼る → 照合して台帳に → 数えて handoff に1行
- **N1 一言ページの形**：`web/missions/*/` を5つの問いの順に（`scripts/build-summaries.mjs`）。新しい事実は書かず、カードの値・出来事のカード・Horizons の表・計算だけ
  - Q1 何？（mission・運用）／Q2 いま何が起きた？（status とその note・確認日）／Q3 どこ？（location、探査機は地球からの距離〈Horizons の表のはじめの日の値・惑星は計算・公式の日付つきの値〉、地球のまわりの機体は高さ。VOYASCOPE で見るボタン、MMX は「いまどこ」へ）／Q4 これまで→これから（打ち上げ・出来事のカード〈済み・延期・中止〉・いま・これからの予定。予定がなければ「まだ載せていません」）／Q5 どれくらい？（光で何時間・月〈1,000倍より先は太陽〉の何倍、地球のまわりの機体は速さ・1周・大きさ・重さ）
  - 答えの材料がない問いは出さない（Q5 のない機体がある）
  - 距離が週1回変わるので、`update-horizons` が表を取ったあとにページも作り直してコミットする
  - アルテミス2号のページは前の形のまま（カードではなくツアーの mission.js から作るため）
  - 画面：[`screenshots/m13-n1/`](screenshots/m13-n1/)
- **問いごとの図**（2026-10-30 オーナー：「各部に three.js のイメージと GIF のような図柄を。その部分だけ切り抜いて X に投稿できるように」）：`web/missions/visual.js`
  - 各問いの見出しの下に、16:9 の図（6秒でくり返す）。図の中に、問い・名前・値・出典・「VOYASCOPE voyascope.org・非公式のファンメイド作品」を描く → 図だけ切り抜けば、なんの図か分かる
  - Q1 機体が回る（探査機は遠くを見る部屋の模型。地球のまわりの機体は地球と高さの輪）／Q2 機体から電波の輪／Q3 地球・月・太陽と機体を桁のものさしにならべ、地球から光が進む（地球のまわりは本当の比の高さの輪を回る）／Q4 線の上を光が打ち上げから「いま」へ／Q5 光が届くあいだ時計が進む（地球のまわりは1周の時計）
  - 「画像を保存」（PNG 1280×720）・「動画を保存（6秒）」（H.264 の MP4 を作れるブラウザは MP4、ほかは WebM）
  - 値はページの本文と同じものだけ（`#vis-data`）。地球を描いた図は「地球の画像：NASA Blue Marble」と書く
  - 1つの WebGL で描き、見えている図だけ動かす。動きを減らす設定では止めた絵。JavaScript・WebGL がなければ図は出ない（文字だけで読める）
  - 読み込み：409KB／上限 500KB（新しいグループ `missions`）

### やらないこと

- ニュースの記事を書かない・論評しない（事実と出典だけ。速報サイトにはならない）
- 人物をページの主役にしない（人物は名前・役割・所属だけ。人物のページは作らない）
- 出典のない「いま何が起きた」を出さない。確かめられないあいだは「確認中」と書く
- 入口（起動画面）を作り直さない（2026-10-16 オーナー：いまの形のまま）。ニュースからの入口はページ側で作る

## 5. 計り方の材料

| 方法 | 分かること | 分からないこと | 費用・手間 |
|---|---|---|---|
| ニュース台帳（N0） | カバー率・新しさ | 実際に来た人の数 | 月1回の速報の依頼と照合 |
| Google Search Console | VOYASCOPE が出た検索の語・表示回数・押された回数 | 来た人の動き | 無料。ドメインの所有の確認（オーナーの操作） |
| Cloudflare Web Analytics | ページごとの閲覧数・どこから来たか | 個人（クッキーを使わない方式） | 無料。入れるかはルール5（個人情報）でオーナーの判断 |

## 6. オーナーに決めてほしいこと

1. この目標（5つの問い・カバー率と新しさを主の指標に）でよいか
2. 目安の数字（2026-12 にカバー率50%、2027-03 に70%）
3. 計り方：Search Console を入れるか（オーナーの操作）／Cloudflare Web Analytics を入れるか（**ルール5：個人情報の扱いに関わるので、判断材料だけ出す**。入れる場合は、このアプリの説明に何を集めるか書く必要がある）
4. 最初にやるのは N0（台帳）と N1（一言ページの形）でよいか。N1 は見た目が変わるので、試作を見てから決める
5. N3 で増やす主題の範囲：機体・出来事に加えて「ロケット」「天文現象（日食・彗星）」まで入れるか（`sky-families.md` の範囲の見直しになる）
