## 0. 結論（先に）

- **一次資料を突き合わせると、企画書の想定より参加者が多い。** 5機関（NASA・CNES・DLR・ESA・オーストラリア宇宙庁 ASA）に、機器の中身の段で**スペイン**（INTA・バリャドリッド大学）が入る。ローバーの分光計 RAX は「独・西・日」の3か国で1台
- **企画書の ⚠️・❓ のうち3つは、今日の一次資料で解けた**（2.）。逆に、**時期の数字は機関ごとに食い違っている**（ローバーを降ろす時期・試料を採る時期・重力の比）
- **見える化の筋は「国ごとに光る探査機」より「地球の上のゆかりの地」**。VOYASCOPE の地球の画面の文法（ピン・環・出典）がそのまま使え、国名ではなく**町の名前**（トゥールーズ・ケルン・バリャドリッド・ウーメラ…）が主役になる。図の部品の置き場所を推測で描かずに済む（3.）
- **言葉は「英語1つ＋地名と機器名は現地の表記」から**。データは1つで、日本語版も同じデータから作れる（日本の子にも「MMX は何か国で作った？」になる）

## 3. どんな見える化ができるか（案）

VOYASCOPE がもう持っているもの：地球の画面（ピン・環）、MMX の自前の3D模型（探査・復路・往路の3段。部品の正確な位置は未確認＝C32）、「いまどこ」（`web/mmx/now/`）、出典の作法、「一言でわかる」（`web/missions/`）。

### 案A 地球の上の「MMX ゆかりの地」（おすすめ）

地球の画面に、MMX にかかわる町を光らせる。押すとカード（何をした場所か・一文・出典）。

| ピン | 何をする場所か | 出典の状態 |
|---|---|---|
| 種子島 🇯🇵 | 打ち上げた | ✅ |
| トゥールーズ 🇫🇷 | ローバーの管制・MIRS の運用（CNES） | ✅（MIRS の運用の場所が CNES のどこかは ❓） |
| ケルン 🇩🇪 | ローバーの管制（DLR MUSC） | ✅ |
| パリ（ムードン）🇫🇷 | MIRS のとりまとめ（LIRA） | ✅（LIRA の所在地は LIRA のページで要確認） |
| ニース 🇫🇷 | ローバーの科学のとりまとめ（OCA） | ✅（所在地は要確認） |
| ローレル（米メリーランド）🇺🇸 | MEGANE を作った（JHU APL） | ✅（所在地は要確認） |
| マドリード・バリャドリッド 🇪🇸 | RAX のレーザー（INTA・バリャドリッド大学） | ✅（INTA のどの拠点かは ❓） |
| ウーメラ 🇦🇺 | 2031年、カプセルが降りる | ✅ |
| NASA・ESA の地上局 | 交信 | ❓ どの局か公式に書いていない → 出さない |

- **強み**：国名ではなく町の名前が出るので「うちの町だ」になる（企画書の §4 の考えと同じ）。部品の位置を推測しなくてよい。国を競わせない（全部のピンが同じ大きさ）
- **気をつけること**：地名・国境の扱い（ルール5）。ウーメラは国防の試験場（RULES ルール4：事実として書く）

### 案B 1台の機器の中の国境（入れ子の図）

国 → 組織 → 機器 → モジュール（探査／復路、ローバー）の順に、線でつなぐ図。いちばんの見せ場は **RAX＝独（分光部）・西（レーザー）・日（焦点）**、**IDEFIX＝仏（カメラ・計算機・電源・通信）・独（miniRAD・RAX）**。モジュールの段まではDLRの一次資料で書ける。

- 強み：「協力」がいちばん伝わる。国選択の入口を作れば、自分の国の線だけ太くできる（企画書の「他国は灰色で残す」と同じ）
- 弱み：子どもには抽象的。単体では見せ場が弱いので、案A のカードの中の小さな図にする

### 案C 旅の場面ごとの「いまの出番」

いまどこ（`web/mmx/now/`）の段階に合わせて、出番の国を灯す：往路（通信：ESA の Ka・NASA と ESA の地上局）→ 火星圏・フォボスの観測（CNES の飛行力学・MIRS・MEGANE）→ ローバー（トゥールーズとケルンが交代）→ 採取（C-SMP〈日〉・P-SMP〈米〉）→ 帰還（ウーメラ）。

- 強み：2031年まで、山ごとに主役の国が替わる（企画書の「熱量の山が何度も来る」）。X の投稿の型（出来事に合わせて1段ずつ）とも合う
- 弱み：ローバー・採取の時期は資料で食い違う（1.3）ので、日付は出さず「順番」だけにする

### 案D 探査機の模型で国ごとに光る（企画書の §4 の 2.）

- **部品ごとには光らせられない**：自前の模型は部品の正確な位置を確かめていない（C32）。位置を推測して光らせると、ルール3に触れる
- **モジュールの段ならできる**（DLR の一次資料）：探査モジュールに米・仏の機器、ローバーは仏独。ただ「探査モジュールが全部光る」では、自分の国の部分という感じは弱い
- → 当面は採らない。JAXA が機器の配置図を出したら見直す

## 4. 市場の見方（客観）

- **だれに届けるか**：英語の情報は機関ごとに十分ある（NASA の [MMX のページ](https://science.nasa.gov/mission/mmx)、DLR・CNES・ESA・JHU APL。ドイツ政府の deutschland.de は打ち上げの動画を多言語で出している）。**足りないのは「機関をまたいだ1枚」**：どの機関のページも自分の担当を中心に書いていて、スペインやオーストラリアまで1か所で並べたものは、今回の範囲では見つからなかった（網羅的に探したわけではない）
- **子どもへの届き方**：海外の子どもが VOYASCOPE を自分で見つける道は、いまはない（検索の表示は日本語のページだけ、X は日本語）。届くのは「先生・親・機関や関係者の再投稿」経由。企画書の成功の定義（関係者の引用）は、その意味で筋がよい。子ども本人の数は測れないので、推測で見積もらない
- **今ある手がかり**：Cloudflare Web Analytics（10/1〜21）の訪問260のうち米国110（`changelog.md` 2026-10-21）。巡回プログラムが混ざっている可能性があり、関心の証拠にはまだ使えない
- **時期**：関心の山は打ち上げ（済み）→ 2027年8月の火星到着 → ローバー → 採取 → 2031年の帰還。最初の公開を急ぐ理由は弱く、**2027年夏までに案A を英語で**が稼働（週数時間）に合う
- **弱いところ**：英語のページは、間違いを指摘されたときに直す手が要る（訂正の受け口がまだない＝handoff の判断待ち「連絡の受け口」）。仏独語は確認できる人がいない

## 5. 言葉の進め方（案）

1. **データは1つ**：企画書の §6 の形（機器・役割ごとに1件、`sources` は複数・言語つき、`status` は verified／conflict／unverified）。名前は各機関の自国語ページの表記（例：仏は CNES の仏語ページ、独は DLR の独語ページ）を原文のまま持つ
2. **日本語と英語を同じデータから**：日本語版は「MMX は何か国で作った？」として、日本の子にも使える
3. **仏・独・西は「地名と機器名と出典」だけ現地の表記**（文は英語）。文まで訳すのは、ネイティブの確認ができてから

## 6. 法律が絡みそうなこと（ルール5。判断材料だけ）

| 項目 | 材料 |
|---|---|
| IDEFIX® の名前 | CNES・DLR は ® つきで書く（アステリックスの登録商標）。企画書はロゴを使わない方針。**名前を文字で使うこと自体**、® を付けるかも、オーナーの判断 |
| 機関のロゴ・画像 | ESA のインフォグラフィックは CC BY-SA 3.0 IGO だが、ESA の画像は使わない決まり（handoff）。ロゴは使わない（企画書のとおり） |
| 地名・国境 | 地球の画面にピンを置く。国旗の絵文字・国名の書き方（ESA を「🇪🇺」で表すかなど） |
| 原文の引用 | CNES のプレスリリース（仏語）を要約で持つ。長い引用はしない（企画書のとおり） |
| 訂正の受け口 | 海外からの連絡の受け方（個人情報） |

## 8. 判断してほしいこと

1. **見える化の筋**：案A（ゆかりの地）を先にするか、企画書の案D（模型が光る）にこだわるか
2. **言葉**：まず英語1つ（地名・機器名は現地の表記）でよいか
3. **置き場所**：VOYASCOPE の地球の画面の中（おすすめ：いまの資産がそのまま使える）か、`/mmx/` の下の1ページか
4. **時期の食い違い**：ローバー・採取の時期を「資料によって違う」と並べて見せるか、JAXA が出すまで出さないか
5. 6. の法律の項目（IDEFIX® の名前の扱い・国旗の絵文字・地名）
