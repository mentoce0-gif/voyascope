### 2.3 空いている場所（VOYASCOPE の立ち位置）

- **網羅**は海外サイト、**正確さ**は国内の公式ツールが持っている。**世界の情報を、日本語で、出典つきでつなぐ層**が空いている
- 勝ち筋は「数」ではなく「統合・日本語・出典」。3万個の点はすでに無料で見られる。同じ土俵で戦う理由がない
- いまの差別化（呼べる名前・環・出典・今夜の空）は、世界に広げてもそのまま効く

### 2.4 ポストから分かったこと

- ポストは「50 の新しいサイト」と書くが、宇宙・地球系の 26 件（重複を除くと 25 サイト）を開くと、**7 サイト（8 件）が終了・つながらない**。4 件は移転・改名。番号 3 と 50 は同じサイト、36 はドメインの綴りが違う（付録 A）
- → SNS のまとめは「きっかけ」にだけ使う（RULES どおり）。VOYASCOPE が外へのリンクを増やすなら、**リンク切れの自動検査が要る**
- いまも動いているのは、個人でも保てる大きさに絞ったもの（AstroViewer は個人の運営で、著作権表示は 2001 年から。satellitemap.space は 2019 年から）。終わったものには、大きな会社の実験（Access Mars）やサービスの入れ替え（EO Browser）もある。→ 小さく保ち、データの取得は自動にする
- 目を引くサイトは、どれも**1つの画面で1つのことだけをする**（10万個の星の中を飛ぶ、火星の地面に立つ、地球のまわりの物体を全部見る）。VOYASCOPE も「部屋」ごとに見どころを1つに絞る（6.）

## 5. 世界に広げても質を落とさない約束

1. **出典は運用機関の公式**（NASA・ESA・CMSA（中国の有人宇宙の機関）・ロスコスモス・ISRO・JAXA など）。英語の出典でよいが、カードの文は日本語で書き、意訳しすぎない
2. **日本語の名前の決め方**を固定する：①日本の公的機関（JAXA・国立天文台・気象庁など）が使う名前 → ②運用機関の正式名のカタカナ → ③英名のまま。どれを使ったかを記録する（C6 を広げる）
3. **名前のある標本だけ**。置き方（sky-families §1：標本・帯・予定・置かない）は世界にも同じ。同時に光る固有名は最大 10 のまま、「部屋」を切り替えて世界を見せる
4. データは**自分のサイトから配る**（Actions で取ってコミット）。外が止まっても前回のデータで動く。ブラウザから直接取るのは、条件がよく CORS が開いているものだけ（GIBS・NOAA）
5. 予定は**公式の日付と「延期」だけ**。到着・通過の日時も、公式が出したものだけを書く
6. **品質の基準を数で決め、CI で守る**（7.）

## 8. やらないこと（世界に広げても）

- 3 万個の点を出すこと（数で競わない）
- ポストのサイトなど、非公式のまとめ・追跡サイトへのリンク（見本にするだけ）

- 利用条件を確かめていない画像、出典のない数値
- 人の写真・本人が言っていないセリフ（RULES）
- 任務が公表されていない機体を「隠し要素」にすること（RULES・sky-families §10）
