# タスク014：探査機の距離を JPL Horizons から（M7 v0 のつづき）

ロードマップ：[`docs/roadmap.md`](../roadmap.md) の M7 v0。前のタスク：[タスク013](013-far-room.md)（遠くを見る部屋 v0。距離を出せない4機は「準備中」だった）。
きっかけ：JPL SSD から、問い合わせた使い方で距離を出してよいと返事があった（2026-10-04。記録は [`research/verification/2026-10-03-c14.md`](../../research/verification/2026-10-03-c14.md) の「JPL SSD とのやりとり」）。オーナー：「含めていいよー！」（2026-10-04。問い合わせの例に入っていなかったパーカーも含める）

## 作ったもの

- **週に1回の取得**（`.github/workflows/update-horizons.yml`・`scripts/fetch-horizons.mjs`・`scripts/lib/horizons.mjs`）
  - 毎週月曜 日本時間 9:41 に、Horizons に1機ずつ、間を3秒あけて問い合わせる（6機で6回）。User-Agent は製品名・版・連絡先（リポジトリの URL）入り
  - 1回で、日本時間 0時から6週間ぶん（1日ごと）の、地球の中心からの距離をもらう。Fair Use の「予測どおりに変わるデータはキャッシュして使い回す」に合わせた。取得が何週か失敗しても、表示は続く
  - 値は有効数字5桁に丸めて `web/data/horizons.json`（約4KB）に置く。見る人のブラウザは Horizons を呼ばない
  - 止めるとき・知らせるとき
    - 出力の version（いまは 1.2）が変わったら、何も書かずに止める（出力の形を確かめてから直す）
    - 取れなかった機体は、前回の表がまだ使えれば残し、失敗で終わって知らせる（GitHub がメールで知らせる）。再試行はしない
    - カードに書いた Horizons の説明の原文（`distance.datasheet_quotes`）が、説明から消えていたら、表は書いたうえで失敗で終わって知らせる。Claude Code が説明を読み直して、カードを直す
  - 公開（`pages.yml`）は、ほかの自動更新と同じく、取得が終わったあとに動く
- **カードの距離の書き方に `horizons` を足した**（`schema/probe.schema.json`）
  - `horizons_id`（Horizons の番号）、`supplier`（軌道のもとのデータを出した機関。説明に書かれているときだけ）、`datasheet_quotes`（その原文）、`note`
  - 6機を `horizons` にした：ボイジャー1号・2号、パーカー・ソーラー・プローブ、はやぶさ２、ジェイムズ・ウェッブ宇宙望遠鏡、ベピコロンボ。説明の読み方は [`research/verification/2026-10-04-horizons-datasheets.md`](../../research/verification/2026-10-04-horizons-datasheets.md)
- **画面**（遠くを見る部屋 v0）
  - 部屋を開いた時刻の距離を、表のとなりの2日から出す（線でつなぐ）。表の外（取得が止まって古くなった）や、表を読めないときは「準備中」に戻す（古い値を「いま」と見せない）
  - カード・はしご：3桁に丸めて「約」（例：約258億 km）。「Horizons の計算値（10月4日に取得）」。光の時間も「約」で丸める
  - くわしいカード：「NASA ジェット推進研究所（JPL）の Horizons で、軌道から計算した値です。通信で測った値ではありません」。軌道のもとのデータ（ESA・JAXA・NASA ゴダード飛行力学施設）。出典は JPL SSD の希望の形：`Solar System Dynamics. (Downloaded 2026, October 4). Horizons System. https://ssd.jpl.nasa.gov`
  - 「距離の出し方」と「このアプリについて」にも書いた
  - 飛ぶ画面の数字（右上）は、有効数字5桁に丸めた値になる（例：70,483,000 km）。1光日（約259億 km）の手前か先かを、半日ほどの細かさで分けるため
