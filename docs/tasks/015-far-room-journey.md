# タスク015：遠くを見る部屋を、合わせた試作の見た目に（M7 v0 のつづき）

ロードマップ：[`docs/roadmap.md`](../roadmap.md) の M7 v0。前のタスク：[タスク013](013-far-room.md)（部屋 v0）・[タスク014](014-horizons-distances.md)（探査機の距離を JPL Horizons から）。
きっかけ：オーナー「そもそもモック版として作って貰ってた画面が反映されてないから」（2026-10-04）。公開中の部屋は v0（2D の簡単な画面）のままで、合わせた試作（[`docs/design/far-room-visual-merged.html`](../design/far-room-visual-merged.html)、[`far-room-feel.md`](../design/far-room-feel.md) §7）の画面は本体に入っていなかった。
これで [`far-room-feel.md`](../design/far-room-feel.md) §7-6 の「three.js を本体に入れるか」は、入れることになった。

## 作ったもの

- **3D の旅**（`web/js/far/journey.js`。試作の script を、本体のデータで動くようにしたもの）
  - 見た目と操作は試作と同じ：画面いっぱいの宇宙に、左下に大きな名前と説明、右上に地球からの距離、下に物差し、右下に「その先へ →」。スイングバイの弧をつないだ航路、うしろの窓の地球（見かけの大きさは本当の値）、火星の地面の望遠の窓、そばで観測中はなぞって（PC は ← →）まわりから眺める、ワープ（作り話）、音（最初は消してある）、動きを減らす設定
  - 停留所は、部屋に並べるもの（`roomItems`）から作る（`journeyStops`）：距離があって、見せ方（`LOOK`）が決まっているものを近い順に。距離は試作の固定値ではなく、開いた時刻の計算値と Horizons の値（1分ごとに計算し直す）
  - 文はカードと予定だけから：探査機は「いま」（`location`）、月・太陽は光の時間、予定は日本時間と残り（名前のすぐ下なので「ベピコロンボが」などの機体の名前は省く。試作と同じ）。「探査機をもっと知る」は、本体のくわしいカード（出典つき・`fullCardHtml`）を開く
  - **停留所が8か所 → 11か所**（2026-10-04 の値で）：月・ウェッブ・はやぶさ２・パーカー・太陽・ベピコロンボ・パーサヴィアランス・ジュノー・ニュー・ホライズンズ・ボイジャー2号・1光日。試作のときは距離が「準備中」だった はやぶさ２・パーカー・ボイジャー2号が、タスク014 で距離を出せるようになったので足した（模型は Codex のもの。試作のメモ「ボイジャー2号は、いまの距離が分かるまで置かない」のとおり）
  - **ボイジャー1号**は停留所を作らず、試作と同じく1光日の輪のそばに置く（いまの距離は約258億 km で、1光日のすぐ手前）。1光日の説明の小さな行に「ボイジャー1号は いま約258億 km・Horizons の計算値（10月4日に取得）」。1光日を越えたら（11/18 予定）、模型は輪の向こう側に置く
  - 向かうときの言葉（「小惑星をめざす、旅の途中へ。」など）は、新しい3か所にも同じ調子で足した。カードに書いてあることだけで書いた
  - 右上の距離の横の印：目安・日付つきの値は「目安」（試作と同じ）、Horizons の値は「計算値」
- **探査機の模型**（`web/js/far/models.js`）：Codex が作った `docs/design/far-room-models.js` を、そのまま置いた（公式を参考にしたイメージ）。模型が見えているあいだだけ「公式を参考にしたイメージ」と出す（試作と同じ）
- **部屋の画面**（`web/js/far/room.js`・`web/css/far.css`）
  - 上の帯：「‹ 地球へ戻る」・VOYASCOPE（起動画面と同じロゴの画像）・遠くを見る部屋・音・距離のはしご。試作の「VOYASCOPE」の場所に、部屋を出るボタンを足した
  - 距離のはしご：Codex 案の形（「遠さにも、階段がある。」、段ごとの丸と縦の線、×10 FARTHER、左の番号＝旅の停留所の番号）。目安・日付つき・Horizons の値は丸めて「約」、計算した値はぜんぶの桁。名前を押すと、その場所まで飛ぶ
  - 終わり：「地球の輪の外は、桁が違う。」「もう一度、地球から」。その下に「距離の出し方」（Horizons の出典は SSD の形のまま）と、キーボードの使い方、非公式ファンメイドの注記
  - くわしいカード：試作の形（MISSION / 探査機を知る）にした。中身は v0 と同じ（事実ごとに出典）
  - 横にしたスマホ・低い窓（高さ 520px まで）：飛ぶ画面を画面の高さに収める（下のボタンと物差しに届くように）。うしろの窓・章・英名の札・なぞる案内は出さず、説明は3行まで
  - スマホで「なぞって眺める」の案内が、長い説明（2行の予定など）と重ならないよう、説明の上の端を測って、それより上に置く
- **3D を使えないとき**：three.js を読めない・WebGL を使えない端末では、v0 の飛ぶ画面（`fly.js`。Canvas 2D）に切り替える。上の帯・はしご・カードは同じ
- **three.js**（`web/vendor/three-r128.min.js`）：r128 の、使う部品だけを esbuild でまとめた（gzip 後 約108KB。もとの three.min.js は約149KB）。MIT（`three-r128.LICENSE`）。作り直し方は `web/vendor/README.md`
  - 新しい版ではなく r128 にした理由：試作と模型が r128 で作られていて、新しい版では光の強さ・色の扱いが変わり、見た目が変わるため（`far-room-feel.md` §7-5 の見込みでは「新しい版」と書いていた）
  - ES モジュールとして `import()` で読み、`window.THREE` は作らない（地球の画面の globe.gl の部品は、起動のときに `window.THREE` があればそれを使う作りなので、混ざらないようにした）
- 「このアプリについて」：部屋の説明に「天体・機体の配置とスイングバイの航路は演出、探査機の模型は公式を参考にしたイメージ」を足し、使っているものに three.js r128（ライセンス）を足した

## 読み込み量

- 遠くを見る部屋を開いたときに読むもの：46KB → **208KB**（gzip 後）。上限を 60KB → **230KB** に上げた（`config/size-budget.json`）
  - three.js r128（使う部品だけ）108KB、3D の旅 34KB、模型 10KB、ほか（部屋・カード・CSS・天体の計算・データ）56KB
  - 起動の読み込み量は変わらない（770KB。index.html の説明の文が少し増えただけ）。部屋の部品は、入口にマウスを乗せた・指で触れたときから読み始める（v0 と同じ）
- 3D の準備（模型・星雲の絵）は、はじめて部屋を開いたときに、部屋を出してから行う（部屋の文字は先に見える）
