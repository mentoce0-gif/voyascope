# タスク009：次の出来事＋これから行く（MMX）

ロードマップ：[`docs/roadmap.md`](../roadmap.md) の「次の段階」M8 v0・M4 v0。案は [`docs/world-plan.md`](../world-plan.md)、見た目は イメージ図（キャンバス）。

## きっかけ

目標「日本語で、世界の情報を統合した高品質な Web アプリ」（2026-10-01 オーナー）の最初の一手。10/20 の MMX の打ち上げに間に合わせる（2026-10-01 オーナー承認）。

## 作ったもの

- **上のバーの「次の出来事」**（PC）：いちばん近い予定と残り時間（「10/20 MMX の打ち上げ あと18日10時間」）。押すと一覧の「予定」を開く。幅が狭い画面（1100px 以下）では出さない
- **一覧の「予定」タブ**：日本と世界の公式の予定を日付順に。日付（日本時間）・種類・日本／世界・残り時間・出典の機関名。先頭に、選んだ県の今夜〜明日の ISS の見える通過（計算）を出す
  - タブは「すべて・家族」と「予定・観測」の2つのまとまりにした。PC で6つが1行に入らないときは、2つ一緒に次の行へ
  - スマホでは「予定」を選ぶと、地球の上も射場のピンだけにする（ほかのタブと同じ「一覧のタブが地球も絞る」）
- **詳細パネル（予定）**：説明・残り時間（時刻まで決まっている予定は毎秒）・日時（日本時間。発表が別の時間帯ならその原文も）・予備期間・ロケット・射場・状態・出典（どの項目の出典か）・公式のページ
- **射場のピン**：地球の上のひし形（◇）と「種子島 10/20」。押すと詳細を開いて地球をそこへ向ける。下の凡例「予定」で消せる。打ち上がるまで軌道は描かない
- 延期：`status` を `postponed` にすると、残り時間を出さず「延期」と出す。新しい日時が公式に出るまで一覧に残す
- 時刻まで決まっている予定は、その時刻から6時間は「予定の時刻を過ぎました」と出して残し、そのあと消える。日付だけの予定は日本時間の翌日いっぱいまで残す（発表した国との時差のため）

## データ

- `curation/events/*.json`（新しいスキーマ `schema/event.schema.json`）。日時は `at`（時刻まで・UTC）／`date`／`from`・`to`／`month` の4通りで、発表の細かさのとおりに書く。事実の項目はすべて出典と確認日つき
- `npm run validate` が予定も検証する（出典・日付の書き方・ありえない日付・逆向きの期間・打ち上げの射場）
- `npm run sync:web` で `web/data/events.json` にまとめる。アプリは読めなくても地球と機体を出す
- 入れた予定（出典の確認：[`research/verification/2026-10-01-events.md`](../../research/verification/2026-10-01-events.md)）

| 予定 | 日時（日本時間） | 出典 |
|---|---|---|
| MMX の打ち上げ（H3 10号機・種子島） | 10/20（火）4:41:03。予備期間は 11/7 まで | JAXA |
| ボイジャー1号が地球から1光日に | 11/18（水）19:16:07 | NASA |
| ベピコロンボが水星を回る軌道に入る | 11/21（土）（日付だけ） | ESA |

## 予定が動いたときの手順

1. Grok に **G4**（予定の動き）を頼む。依頼文の最後に「確かめる予定」を書く
2. 公式の発表を Claude Code が確かめる
3. `curation/events/` を直す（延期なら `status`、新しい日時なら `when`。どちらも出典つき）→ `npm run validate` → `npm run sync:web`

## 確かめたこと

- テスト（`tests/events.test.mjs`、11件）：日本時間・曜日・年の表示、日本時間で日付が変わる時刻、残り時間のことば、延期、並べ替えと消えるまでの時間、出典の機関名、文字のエスケープ、今夜の通過を先頭に、詳細の出典、curation と web/data の一致
- ブラウザ（Chromium、時刻を 2026-10-01 18:20 日本時間に固定）：次の出来事・一覧・詳細・残り時間が1秒ずつ減る・閉じる・機体を選び直す・凡例で予定を消す。PC 1440×900、スマホ 390×844。画面：[`docs/screenshots/events/`](../screenshots/events/)
- 予定を開いたまま90秒：描画の速さ（ソフトウェア描画で毎秒10〜11コマ）とメモリは変わらず、main と同じくらい

## やらないこと（このタスクでは）

- 世界の打ち上げ（Launch Library 2）：利用条件（C8）を確かめてから M4 v1 で
- 予定の日時の自動取得：公式の発表を人が確かめて直す（推測で日付を動かさない）
- 打ち上げの中継の埋め込み（公式の画面は枠に入れない）
