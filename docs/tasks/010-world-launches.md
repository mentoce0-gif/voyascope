# タスク010：世界の打ち上げ（参考）

ロードマップ：[`docs/roadmap.md`](../roadmap.md) の M4 v1。案は [`docs/world-plan.md`](../world-plan.md)。

## きっかけ

C8（Launch Library 2 の利用条件）を確かめたあと、オーナーが決めた（2026-10-02）：

> 企業でもないし、楽しむためのものだから、公的情報じゃないマークを作りましょう。それをつけてるやつはホバーで「The Space Devs 参照（正確な情報は公式サイトを確認ください）」と表示する。

Claude Code から足した2点（オーナーに伝えたうえで実装）：

- スマホにはホバーがないので、押して開く詳細には同じ文を**いつも**出す
- 画面の読み上げにも同じ文が入るようにする（一覧の行と地球のピンの説明＝`aria-describedby`）

## 作ったもの

- **「参考」の印**：点線の小さな札「参考」。公式の予定（ミント色・実線）と見分けられるように、参考の情報は**点線と青灰色**でそろえた
  - 一覧の行・地球のピンにマウスを乗せる（キーボードで選ぶ）と、少し待ってから「The Space Devs 参照（正確な情報は公式サイトを確認ください）」の吹き出しが出る
  - 詳細パネルでは、同じ文を一番上にいつも出す
  - 読み上げでは、行とピンの名前のあとに同じ文を読む
- **一覧の「予定」タブの下の段「世界の打ち上げ」**：公式の予定の箱とは分け、点線の箱にした。日時（日本時間）・任務の名前・射場（日本語の名前と国）・ロケット・残り時間。最後に説明と取得の時刻
- **詳細パネル（世界の打ち上げ）**：説明の文・残り時間（Go で分まで出ているものは毎秒。札は「打ち上げまで（参考）」）・日時（日本時間。時刻の確かさと、打ち上げられる時間の終わり）・ロケット・担当（会社・機関）・任務（種類と行き先）・射場・状態（The Space Devs の区分）・出典（取得の時刻と The Space Devs の更新の時刻）
- **地球のピン**：点線のひし形と「ケネディ 10/2 参考」。**「予定」タブを開いているときだけ**出す（ホームの地球に光る名前を増やさない。sky-families §1 の「同時に光る固有名は最大 10」）。近い射場（ケネディとケープカナベラルなど、60 km 以内）は1本にまとめる。公式の射場のピンと重なるところには立てない
- 一覧の行にマウスを乗せると、同じ射場のピンが光る（どこの打ち上げかを目で追えるように。公式の予定の行も同じ）
- スマホで一覧を全部の高さに広げたときは、上に少しだけ見える地球の名前を消す（上のバーの文字と重なるため）

## 公式の予定との関係

- 上のバーの「次の出来事」は**公式の予定だけ**（変えていない）
- 公式の予定と同じ打ち上げ（射場が 60 km 以内で、日時の差が2日以内）は、公式の方だけを出す。いまは MMX がこれに当たり、世界の打ち上げには出ない
- 公式の予定が「延期」のあいだは突き合わせない（公式の新しい日時はまだないので、The Space Devs の日時は参考として別に出る）

## データ

- 取得：`scripts/fetch-launches.mjs`（GitHub Actions の update-orbits で6時間ごと。手元では `npm run fetch:launches`）。呼ぶのは1回だけ（無料は1時間15回まで）。本番の `ll.thespacedevs.com`（`lldev` は開発用でデータが古い）
- 残すもの：状態が **Go（日時が確かめられている）か TBC（公式の確認待ち）** で、日時が**日付以上の確かさ**（秒・分・時・午前・午後・その日）のもの。45日先まで、最大12件。弾道飛行（宇宙の入口まで上がって戻る飛行）は入れない
- 作り直し（`scripts/lib/launches.mjs`）：受け取った JSON をそのまま置かず、必要な項目だけにして、射場・国・会社・任務の種類・行き先に日本語の名前を付ける（`config/launches.json`。自信のない名前は書かず、英名のまま出す）→ `web/data/launches.json`
- 失敗したとき：200 以外や形が違うときは、再試行せずに止まり、前回のデータが残る。1〜2回の失敗（混み合い）では知らせず、**前回の取得から36時間たったら**ワークフローを失敗にして知らせる（GitHub がメールで知らせる）
- 画面では、**取得から48時間たったデータは出さない**（「データが古くなっているので、いまは出していません」）。古さは時刻を動かしても実際の今で判断する
- 自動更新が「失敗」で終わっても、Pages は公開し直すようにした（`pages.yml`）。失敗は軌道データをコミットしたあとで知らせるためのことがあり、公開を止めると軌道データまで古くなるため
- 最初のデータ：2026-10-01 23:00 UTC に本番から1回取得したもの（7件。11/24 のプログレス補給船は45日より先なので入らない）

## やらないこと（このタスクでは）

- The Space Devs の画像・説明文・中継のリンク：画像は利用条件がまちまち（CC BY-NC など）で、説明文は英語のまま転載になるため
- 打ち上げ会社の公式サイトへのリンク：The Space Devs のデータにあるリンクは確かめていないので、まだ付けない（名前を出して「公式サイトで確かめて」とだけ書く）
- 日付が月・四半期・年までしか決まっていない打ち上げ（TBD を含む）：遠い先の目安は推測に近いので出さない
- 打ち上げ後の結果（成功・失敗）：公式の発表で確かめてもらう
