# タスク012：スマホで軽くする（読み込みの順番を直す・読み込み量の上限を CI で守る）

ロードマップ：[`docs/roadmap.md`](../roadmap.md) の M6「2週目：公開準備」の「スマホでの重さ」。見た目は変えない。

## 測ったこと（2026-10-02）

- 条件：Lighthouse のスマホの既定に合わせて回線を絞る（往復 150ms・下り 1.6Mbps）＋ CPU を4倍遅く。画面 390×844。Chromium（ソフトウェア描画）。キャッシュなし
- 公開ページでは、「観測を開始」を押せるまで約11秒（11.1秒・11.3秒）
- 読み込みの順番を調べて分かった原因
  1. 3D 表示のライブラリ（globe.gl、gzip 後 514KB）を、ページの `<script>` で読んでいた。届いて実行し終わるまで、アプリの部品（`js/`）とデータの読み込みが始まらなかった（6.2秒まで待っていた）
  2. 機体のカードと軌道は、ほかのデータ（陸地の形など）がすべて届いてから読み始めていた
  3. ミニ地図にしか使わない陸地の形（`land-110m.geojson`、140KB）を、起動のときに読んでいた
  4. Google Fonts の CSS が届くまで、画面に何も出なかった（最初の表示まで 2.4〜3.0秒）

## 直したこと（見た目は変えない）

1. **3D 表示のライブラリを、ほかの読み込みを止めずに読む**：`<link rel="preload">` で最初に読み始め、実行は `js/main.js` がする。データの読み込みと並べて待つ。届かなければ、これまでどおり起動画面に「3D表示のライブラリを読み込めません」と出す
2. **機体のデータを先に読む**：機体の一覧（`craft-index.json`）が届いたら、すぐに各機体のカードと軌道を読み始める
3. **重いデータはあとから読む**
   - ミニ地図の陸地は、前もって計算した線（`data/land-minimap.json`、gzip 後 29KB）にした。これまで画面で毎回計算していた線と1文字も変わらない（`scripts/build-minimap-land.mjs` で作り、最新かどうかはテストで確かめる）
   - 陸地と地名（`places.json`）は、「観測を開始」を押せるようになってから裏で読む（ボタンを押すまでの時間を使う。地名はこれまで観測を始めてから読んでいた）
   - 届く前にミニ地図を開いたときは、海と軌跡と現在地だけを描く。届いたらすぐに陸地を描き足す。読めないときは、これまでどおり座標だけ・海と軌跡だけで動く
4. **フォントを待たずに画面を出す**：Google Fonts の CSS を、画面の表示を止めない形（`media="print"` → 届いたら `all`）で読む。届くまでは端末の文字で出し、届いたら入れ替わる（フォントの中身が届くまでの動きは、これまでも同じ）

## 結果（同じ条件で前後を比べる）

手元に GitHub Pages に近いサーバー（HTTP/2・gzip）を立て、同じ絞り方で2回ずつ測った。上の約11秒は公開ページ（実際の回線も通る）での値なので、この表の「前」とは条件が違う。

| 遅い4G・CPU 4倍 | 前 | 後 |
|---|---|---|
| 「観測を開始」を押せるまで | 7.9〜8.1秒 | **6.2〜6.5秒** |
| 最初に何か映るまで | 2.4〜3.0秒 | **1.2〜1.3秒** |
| 起動画面がそろうまで（いちばん大きい表示） | 3.6〜4.0秒 | **2.8〜3.0秒** |
| 押してから地球の画像がそろうまで | 7.9〜8.0秒 | **4.7〜6.2秒** |
| 全部の読み込み量 | 1,796KB | **1,685KB** |

- 速い4G（往復 40ms・下り 10Mbps・CPU 4倍）：最初に映るまで 1.0〜1.5秒 → 0.6〜0.9秒。「観測を開始」まではどちらも2〜3秒（この速さでは回線より計算の時間で決まる）
- データは2.3秒で読み終わるようになった。遅い回線でいま時間がかかっているのは、3D 表示のライブラリ（514KB）が届くまで（約5.5秒）
- 1コマの重さ（地球を回すときの滑らかさ）は、ここ（ソフトウェア描画）では実機と比べられない。実機で確かめる

## 読み込み量の上限（CI）

- 上限は `config/size-budget.json`、確かめるのは `scripts/check-size.mjs`（`npm run check:size`）。validate のワークフローで毎回確かめる
- 数え方：文字のファイル（html・css・js・json）は gzip 後、画像はそのまま。Google Fonts（外のサイト、起動のときに約250KB）は数えていない

| 対象 | いま | 上限 |
|---|---|---|
| 「観測を開始」を押せるまでに読むもの | 765KB | 850KB |
| あとから読むもの（地球の画像・地名・ミニ地図の陸地・機体の画像） | 734KB | 820KB |
| 1ファイル（`web/` のすべて） | 514KB（globe.gl） | 600KB |

- 起動の決まり（`index.html`）も確かめる。今回直したことが戻らないように
  - `<script src>` は `type="module"`・`async`・`defer` のどれか
  - 外のサイトのスタイルシートは、画面の表示を止めない形で読む
  - globe.gl は `<link rel="preload" as="script">` で最初に読み始める
- 上限を超えたら、まず小さくできないか（画像を縮める・あとから読む）を考える。上げるときは理由を PR に書く

## 確かめたこと

- テスト 72件（新しく7件：起動の決まり・数えるファイル・ミニ地図の陸地が最新・陸地が届く前のミニ地図）。`npm run check:size` は、直す前の `index.html` の3つの問題をすべて見つける
- ブラウザ（Chromium、時刻を 2026-10-02 15:00 日本時間に固定）
  - PC 1440×900・スマホ 390×844：起動 → 観測を開始 → ISS の詳細（いま：太平洋の上）→ 軌道のタブのミニ地図に陸地。前と後の画面写真を並べ、見た目が同じことを確かめた（違いは走査線とロゴの明滅のアニメーションだけ）
  - globe.gl は1回だけ読み込まれる（preload したものを使う）
  - 陸地のデータを40秒遅らせる → 先に開いたミニ地図は海と軌跡だけ、届いたら陸地が描き足される
  - 陸地と地名が読めない → エラーなし。座標だけ・海と軌跡だけで動く
  - globe.gl が読めない → 起動画面に「読み込みに失敗しました：3D表示のライブラリを読み込めません」と出て、ボタンは押せないまま
  - コンソールのエラーなし

## やらないこと（このタスクでは）

- 3D 表示のライブラリを小さくする（three.js と globe.gl を自分で組み立て直す）：効果はいちばん大きいが、ライブラリの扱い方が変わるので別に相談する
- フォントを自分のサイトから配る（使う文字に絞る）：見た目にかかわるので別に相談する
- 地球の画像を先に読んでおく：ブラウザのキャッシュの効き方しだいで、効果が読めないため
- 実機（iPhone・Android）での確認：オーナー
