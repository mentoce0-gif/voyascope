## M9　Cloudflare への移行と公式ページの見張り（半自動化）⏳

2026-10-02 オーナー：しばらく手動で回し、Cloudflare で半自動化するときに検討する。

- 進め方（2026-10-02 オーナー）：ページがある程度できあがるまでは、効率のよい GitHub（Pages・Actions）で形にする。順番は **M6 → M7 v0（遠くを見る部屋。体感の検討を含む）→ Cloudflare への移行を検討**。ページの構成が固まった目安を M7 v0 の完了とし、そのときに Claude Code が移行の段取りを提案する
- 理由：コミットが多いと公開の処理が詰まって失敗しやすい（オーナーのブログでの経験）。GitHub の間は「変化があったときだけコミットする」を守る
- M9 を M10〜M12（今日の地球・宇宙天気・宇宙にいる人）より先にする理由（2026-10-02）：M10・M11 は毎日〜数時間ごとに取りにいくデータが中心。GitHub のままで作ると、更新のたびのコミットで公開の処理が増え、あとで Cloudflare 向けに作り直すことになる。移した後で作れば、一度で済む
- 移すときに、`CLAUDE.md` の方針「サーバを持たない。GitHub Pages ＋ GitHub Actions ＋ ブラウザ内計算で完結させる」を書き直す（管理するサーバを持たない点は変わらない。完結させる場所に Cloudflare が加わる）

- 当面（手動）：動きは Grok の速報（G2・G4）、載せた値の差分は Claude Code が公式ページを直接開いて確かめる
- 半自動化で決めること：見張る対象（curation/ の出典URL＋公式の一覧ページ）／比べる相手は「載せている値」に固定する／通知は変化があったときだけ／反映は今まで通り Claude Code が確かめてから
- 検討の材料：curation/ から見張り表を自動で作る試作（[PR #24](https://github.com/mentoce0-gif/voyascope/pull/24)、マージせずに閉じた）。ChatGPT の dots で試そうとしたが、定時検索として組まれたため取りやめ（2026-10-02）
- AI を使わない方法（GitHub Actions で出典ページの日付・リンク切れを定期チェック）は Q と重なるので、あわせて比べる
