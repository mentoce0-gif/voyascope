# X の下書き（@voyascope）

下書きを作るだけ。**投稿・いいね・フォロー・リプライの送信はしない**（オーナーが「私口調」に直して手で出す。自動ツールは使わない）。

## 先に読むもの

- `RULES.md`・`CLAUDE.md`（最優先ルール5点）・`docs/handoff.md`（いまの出来事と、凍結の期間）
- 迷ったら止めて聞く。とくに **法律が絡みそうなこと**（他人の画像・動画・ロゴを投稿に入れる、機関の名前を「公認」に見える形で使う、人物の情報）は、判断材料をまとめてオーナーに出す

## 方針（2026-10-15 オーナー）

- 軸は **動く画面** と **型を固定した短い投稿**。「今夜使える」と「引用」は時々
- 人物を話題のフックにしない。**オーナーと Claude で作ったもの（アプリの画面・場面）の GIF／動画** を貼る
- 文言は **短いフック** にする（1行目で止まる言葉。説明は1〜2行まで）

## 投稿の型（どれか1つを選ぶ）

| 型 | いつ | 中身 | 目安 |
|---|---|---|---|
| A 今夜使える | ISS が夕方〜夜に見える週、流星群の極大の前日〜当日 | 県ごとの時刻・方角（下の計算で出す）＋アプリの画面 | 時々（見える週に1本ほど） |
| B 出来事の日 | MMX の打ち上げ、ボイジャー1号の1光日（11/18）など | 動く画面＋その出来事の「前」と「後」。出来事の最中は公式の中継が見られるので出さない（2026-10-15 オーナー：打ち上げのときはみんな VOYASCOPE を見ない）。前は予告・何の機体か、後は「いまどこ」・距離・次の節目 | 主軸 |
| C 引用 | 大きな宇宙・天文・教育のアカウントの投稿 | 元の投稿に、VOYASCOPE でしか出せない数字か画面を1つ足す（公式にない「その後」「距離の感覚」など）。公式を否定しない | 時々 |
| D 開発記録 | 新しい場面を出したとき | 何ができるようになったか（作った話より、見える物） | 週1本まで |
| E リプライ | オーナーが元の投稿を貼ったとき | 「アプリで見るとこうだった」の具体を1つ | オーナーの時間しだい |

## 1本の形

1. 素材：**動く画面（10〜15秒の録画）を優先**、なければ静止画。画像は本文に
2. 1行目：短いフック（「20日4:41、種子島のピンが光ります」「明日の明け方、ISS が頭の上」など。数字を入れる。誇張しない）
3. 実用の情報：時刻・方角・数字（下のルールで確かめたものだけ）。1〜2行まで
4. 非公式のファンメイドである一文（プロフィールで足りるかはオーナーの判断。迷ったら入れる）
5. リンク（voyascope.org の該当ページ）は **いまの決まりどおり返信に**（2026-10-12 オーナー）。本文に入れて比べたいときは、オーナーに A/B を提案する
6. ハッシュタグは0〜1個

長さは X の重み付きで280以内（日本語1文字＝2）。2案出す（言い回しの違い）。

## 事実のルール

- **ISS の時刻・方角は、自分で書かずに計算で出す**（アプリと同じ `web/js/passes.js`）：

  ```
  node .claude/skills/x-post/scripts/tonight.mjs            # 札幌・東京・名古屋・大阪・福岡、2日ぶん
  node .claude/skills/x-post/scripts/tonight.mjs 宮城 沖縄 --days 3
  ```

  - 時刻は「ごろ」、場所は「県の代表地点（県庁のあたり）」と分かる書き方にする。天気しだいである一言を入れる
  - 軌道データが3日より古いと警告が出る。投稿の直前（数時間前）にもう一度出して、ずれていないかオーナーに確かめてもらう
  - 見える通過が明け方だけの週は「今夜」と書かない（その週は A をやめて B〜D にする）
- そのほかの数字・日時は、`curation/` のカード（出典つき）か、公式ページで確かめたものだけ。SNS（引用元の投稿・Grok）の数字はそのまま使わない
- 人物をフックにしない（2026-10-15 オーナー）。出てくるときも名前・役割・所属だけ
- 打ち上げの成否・延期は、公式の発表が出てから書く。「祈ってます」などの気持ちはオーナーの言葉に任せる

## 素材（画面の録画）

- オーナーがスマホで画面録画するのがいちばん手早い。どの画面で何を見せるか（例：「県を選ぶ → 今夜の通過が出る」「種子島のピンが光る」）を、下書きに **10秒の段取り** として書く
- Claude Code が作るときは、Chromium（Playwright）で `web/` を開いて録画し、ffmpeg で mp4（X 向け）と GIF にする。作ったものは `SendUserFile` で渡す（リポジトリに入れない）
- 打ち上げの日のビーコン：`scripts/record-launch.mjs`（アプリの時計だけを打ち上げの数秒前に進めて、カウントダウン → ビーコンが光る瞬間を撮る）
  ```
  npx serve -l 5179 web &
  node .claude/skills/x-post/scripts/record-launch.mjs http://localhost:5179/ <出力先> 390 844 6
  ffmpeg -ss <cut> -i <出力先>/*.webm -t 15 -c:v libx264 -pix_fmt yuv420p -movflags +faststart mmx-beacon.mp4
  ```
  - 最初の3秒に動き（カウントダウン・ピン）が入るようにする
  - 先の日時の画面なので、投稿には「当日の画面（時計を進めて撮影）」と書く。延期で日時が変わるとビーコンは出ない（`web/js/launch-plan.js` の forAt）

## 出すもの

- 下書きは、`voyascope-research` の `research/outreach/YYYY-MM-DD-x-<話題>.md` に置く（そのリポジトリが使えないセッションでは、チャットに出す）
- 1本ごとに：型・素材の段取り・本文2案・返信に置くリンク・確かめた出典・投稿にいい時間帯

## 振り返り（数字で決める）

- オーナーが出したら、48時間後のインプレッション・いいね・リンクのクリック・プロフィールへのアクセスを、下書きのファイルに貼ってもらう
- 4週ごとに、型ごと（A〜E）・素材ごと（動画／静止画）・リンクの位置ごとに並べて、どれを増やすか提案する。Grok などの助言は仮説として扱い、ここの数字で入れ替える
