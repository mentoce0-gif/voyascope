## MITライブラリを同梱する場合の実装

VOYASCOPEの構成としては、次の分離が扱いやすいです。

```text
/
├─ LICENSE
│   └─ VOYASCOPE自作コード
│      Hippocratic License 3.0 + Military Activities
│
├─ THIRD_PARTY_NOTICES.md
│   ├─ satellite.js — MIT
│   ├─ globe.gl     — MIT
│   └─ three.js     — MIT
│
├─ CONTENT_LICENSE.md
│   └─ VOYASCOPE独自カード文章
│      例：CC BY 4.0 等
│
└─ README.md
    └─ 各ライセンスの適用範囲を明記
```

MITについて最低限必要なのは、各ライブラリの元の**著作権表示とMITライセンス文を配布物から落とさないこと**です。VOYASCOPEのトップレベル`LICENSE`をHL3にしても問題ありませんが、「repository内の全ファイルがHL3」と書くと第三者MITコードまでHL3のみであるように見えるため避けるべきです。

また、npm等でbundleしているなら**この3つだけで終了とは限りません**。globe.gl自体にも依存パッケージがあるため、実際に配布されるdependencyについてライセンス一覧を作るのが安全です。globe.glの現行package.jsonでもthree-globe等のdependenciesが確認できます。

## コードとカード文を分ける理由

**分ける方が自然です。** HL3は`Software`をかなり広く定義していますが、ライセンスの中心には特許許諾、ソフトウェア改変、派生コード、copyleft等の規定があります。文章・画像・カード解説については、コンテンツ向けに作られたCCライセンスの方が利用者に理解されやすいです。Creative Commons自身もCCをsoftwareには推奨せず、一方でdocumentationやartistic elementsには利用できると説明しています。

たとえば、再利用を広く認めたいカード文なら **CC BY 4.0**、改変も同条件で共有させたいなら **CC BY-SA 4.0** という分け方ができます。ただし、CCには「軍事利用だけ禁止」という標準条件はありません。その制限をカード文にも必須とするなら、別途設計を検討する必要があります。

## OSIについて

ここは明確です。

Hippocratic License 3.0 + Military Activities は、ソースコードを公開できても、**OSIの意味でOpen Sourceとは呼べません**。OSI Open Source Definition §6では、ライセンスは利用分野を制限してはならないとしています。Military Activitiesはまさに軍事活動を行うentity等を排除する条件なので、この基準とは両立しません。

さらにOSIのApproved Licenses一覧は「Open Source Definitionに適合し、OSIの審査を通ったもの」と説明していますが、Hippocratic Licenseはその承認ライセンスとして掲載されていません。

したがってREADME等では、

**「Source code is publicly available under the Hippocratic License 3.0 with the Military Activities module. This license is not OSI-approved Open Source software.」**

のように扱うのが最も誤解が少ないです。

## 食い違い・注意
- **「Military Activities＝軍事利用禁止」だけではない。** 条文は利用目的ではなくLicenseeの属性にも掛かっており、軍事活動を行うentity、そのaffiliateやagent等まで対象とする非常に広い書き方である。
- HL3にはcopyleft条項があり、「modified software, source code, or other derivative work」を同一条件でライセンスするよう要求している。一方、MITライブラリそのもののnotice義務は残るため、**VOYASCOPE自作部分のHL3と第三者MITコンポーネントを明示的に区別する**設計が重要。
- 「GitHubでソース公開している」ことと「Open Source」は同義ではない。VOYASCOPEでHL3-Militaryを採用する場合、**public source / source-available / ethical source**などの表記と、OSI Open Sourceを区別するのが安全。
