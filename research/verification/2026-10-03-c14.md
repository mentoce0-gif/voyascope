## 判断（Claude Code）

- **取り方**：GitHub Actions で1日1回、探査機ごとに1件ずつ順番に呼び、結果を保存して自分のサイトから配る形にすれば、Fair Use Policy の取り方の決まりに合わせられる。決まりの中身は、サイトに埋め込まない・1件ずつ・キャッシュする・失敗したら間をあける・User-Agent に製品名と版と連絡先を入れる、の5つ。ブラウザから Horizons を直接呼ぶことはしない。出力の version も確かめる
  - → 2026-10-04：1回で先の数週間ぶん（1日ごと）をもらって使い回し、取り直しは週1回にする（Fair Use の「予測どおりに変わるデータはキャッシュして使い回す」。下の記録）
- **User-Agent の連絡先**：オーナーのメールアドレスは出さない方針（2026-09-30）なので、リポジトリの URL を連絡先にする案
- **数値を自分のサイトに出すこと**：SSD の FAQ は「許可が要る。少なくとも、何をどう使うかを知りたい。できればリンクで（とくに、よく更新される数値は）」と答えている。なので、本番の距離を画面に出す前に、JPL SSD に用途を伝えて確かめる（オーナーから）。返事があるまで、Horizons の数値は公開ページに出さない
  - → 2026-10-04：JPL SSD から「書いた使い方で問題ない」と返事があった（下の記録）
- **出典表示**：マニュアルの推奨の引用をもとに「NASA/JPL Horizons（取得日）」を出す。出典を書けば許可の代わりになる、とはどこにも書かれていない
  - → 2026-10-04：SSD の希望の形「Solar System Dynamics. (Downloaded 年, 月, 日). Horizons System. https://ssd.jpl.nasa.gov」に替える（下の記録）
- **表示の仕方**：Horizons の値は軌道の計算（予測を含む）なので、「いまの位置」ではなく「Horizons による計算値・取得日」として出す（いまの機体の「計算値」と同じ扱い）
- **ESA・JAXA から来た軌道**（ベピコロンボ・はやぶさ2 など）に別の条件がかかるかは、公開資料では分からない。JPL への問い合わせで一緒に聞く
  - → 2026-10-04：別の条件はない。Horizons の説明（datasheet）にある、もとのデータを出した機関を引き継いで示す（下の記録）

### Fair Use の今の文（2026-10-04 に開いて確かめた）

返事が案内したページ（https://ssd-api.jpl.nasa.gov/）を開くと、はじめに「続けるには、次の決まりを受け入れること」として Fair Use Policy が出る。API の説明のページ（`https://ssd-api.jpl.nasa.gov/doc/index.php`）と同じ文。10/03 に照合した引用（1件ずつ・サイトに埋め込まない・User-Agent）は、そのまま載っている。取り方に関わる文：

- 必要なぶんだけ取る。自動の処理で、むだに何度も・くり返し・重ねて取らない。**変わらないデータや、予測どおりに変わるデータは、できるだけキャッシュして使い回す**（"Where practical, applications should cache and reuse results rather than repeatedly requesting unchanged or predictably changing data."）
- 1件ずつ（同時に呼ばない）
- エラー・回数の制限・止まっているときは、間をあけるか回数を減らす。失敗をすぐにくり返さない
- 自動でつなぐときは、製品名・版・連絡先を入れた、そのアプリだけの User-Agent を付ける
- 負担が大きい取り方や、この決まりに合わない取り方は、制限・遮断することがある
- サイトに API を埋め込まない（NASA の CORS の決まり）
- 出力の形は予告なく変わる。出力の version を毎回確かめる。いつまでも提供されるとは限らない。できる範囲での提供（best effort）

### 返事を受けて直したこと（Claude Code、2026-10-04）

1. **出典の書き方**：SSD の形に合わせる。英語の形はそのまま使い、日本語の説明を添える
   - 出典の行：`Solar System Dynamics. (Downloaded 2026, October 4). Horizons System. https://ssd.jpl.nasa.gov`（日付は取得した日。ページの名前は、Horizons のページ https://ssd.jpl.nasa.gov/horizons/ の題名「Horizons System」。2026-10-04 に確かめた）
   - 日本語の説明：「NASA ジェット推進研究所（JPL）の Horizons で計算した値（○月○日に取得）。いまの通信の値ではありません」
   - 10/03 の案（Horizons のマニュアルの引用 "Giorgini, JD and JPL Solar System Dynamics Group, …"）は、SSD の希望の形に置き換える
2. **もとのデータを出した機関**：機体ごとに、Horizons の説明（datasheet）にある出どころを、距離のそばに「軌道のもとのデータ：ESA」のように書く
   - 取るたびに説明の文も保存する。文が変わったら知らせて、Claude Code が読んで確かめてから書き直す（自動で読み取って書き換えない。推測を入れないため）
   - 説明に出どころが書かれていない機体は、何も書かない（推測で「NASA」などと書かない）
3. **取り方**：探査機の軌道は「予測どおりに変わるデータ」なので、毎日取る形から、**1回で先の数週間ぶんの距離（1日ごと）をもらって使い回し、取り直しは週1回**にする（軌道が新しくなったのを拾うため、週1回は取り直す）。1件ずつ・間をあける・User-Agent（連絡先はリポジトリの URL）・ブラウザから呼ばない・version を確かめる、は変えない。問い合わせに書いた「1日1回・1日5件ほど」より少ない
4. **文書**：ロードマップ・世界の計画・タスク013・遠くを見る部屋の設計の「許可待ち」「返事待ち」「10/17 の代わり」を直した
